# 在 GitHub 网页编辑多行更新说明

GitHub 的 Run workflow 原生表单是单行输入，无法通过工作流配置放大为文本框或拦截回车。**不要在那里写长文。**

## 写多行说明

1. 在仓库 **Code → Add file → Create new file** 新建 `release-notes/1.0.4.md`，将 `1.0.4` 换成你准备发布、尚未使用的版本号。
2. 在下方大编辑器中编写 Markdown，可正常按 Enter 换行；写完后点击 **Commit changes** 保存到 `main`。
3. 回到 **Actions → Build desktop apps → Run workflow**，选择 `main`，填写同样的版本号。
4. 将“单行简述”留空，最后勾选“发布到 Releases”，用鼠标点击绿色 **Run workflow**。

不用额外填写文件路径。`1.0.4` 和 `v1.0.4` 输入都会读取 `release-notes/1.0.4.md`；也接受文件名 `v1.0.4.md`，但同版本只能保留其中一个。

示例结构（请替换为本次实际变更）：

```markdown
### 新增
- 描述本次新增的功能。

### 修复
- 描述本次解决的问题。

### 注意事项
- 如有升级注意事项，在这里说明。
```

## 读取顺序

1. 填了“单行简述”：优先用输入内容。
2. 单行简述留空，存在对应版本 Markdown：使用该文件的多行内容。
3. 两者都没有：自动汇总上一版本后的提交。

Markdown 文件需使用 UTF-8 编码，不超过 10000 个字符。空文件、重复文件和符号链接会被拒绝，避免发布不完整或错误内容。文件属于源码提交，发布只读取本次构建提交中的文件；之后再修改文件不会影响已完成的 Release。

提交 Markdown 文件可能自动触发一次普通构建，但**不会正式发布**；正式发布仍需你在 Run workflow 中勾选发布选项。
